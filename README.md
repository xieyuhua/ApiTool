# ApiTool · 接口调试与文档工具

本地优先的 API 接口调试、管理与文档生成工具。基于 **Wails + Vue + Go** 构建为桌面应用，
同时内置可独立部署的**云同步 / 分享服务器**，实现「本地开发 + 云端分享」。

- 本地数据自动保存，无需登录即可使用
- 多项目 / 多目录 / 多接口管理，目录树宽度可拖拽、默认折叠、加载有指示
- 环境变量、`{{变量}}` 自动替换、前后置脚本（支持对象/数组取值）
- **公共参数**：项目级统一的 Header / Query，自动附加到所有接口
- AI 自动生成字段说明
- 一键导出 Markdown / HTML / Word / OpenAPI 文档
- 两种分享方式：**网页代码（独立 HTML）** 与 **在线链接（本地或云服务器）**
- 云同步 / 多端共享、内置同步服务
- 本地 JSON 配置 + 客户端自动升级检测
- **剪贴板历史**：系统级监听，连续按两次 Ctrl 调出浮层，自动记录复制过的文本与图片，支持搜索、快捷复制/删除

> **开发者文档**：代码架构、模块依赖、构建与贡献约定见 [`ARCHITECTURE.md`](./ARCHITECTURE.md)；历史重构记录见 [`REFACTOR_PLAN.md`](./REFACTOR_PLAN.md)。

## 二、安装与构建

### 环境要求
- Go 1.26+（与 `go.mod` 一致）
- Node.js 18+
- Wails v2 CLI：`go install github.com/wailsapp/wails/v2/cmd/wails@latest`

### 构建桌面应用
```bash
cd apitool
wails build
```
产物位于 `build/bin/apitool.exe`（Windows）/ `build/bin/apitool`（macOS/Linux）。

### 开发模式（热更新）
```bash
wails dev
```
会启动 Vite 开发服务器；也可在浏览器访问 `http://localhost:34115` 进行前端调试（无 Go 后端时部分功能降级为友好提示）。

### 构建云同步 / 分享服务器（独立部署到云）
```bash
go build -o build/bin/apitool-server.exe ./server/cmd
```
运行：
```bash
apitool-server.exe -addr :8080 -data apitool-server-data
```
- `-addr`：监听地址，如 `:8080` 或 `0.0.0.0:8080`
- `-data`：数据存储目录（用户账号、项目、分享文档）

## 三、使用指南

### 1. 项目与目录
- 顶部项目下拉框右侧「⋯」菜单：**新建项目 / 重命名当前项目 / 删除当前项目**。
- 侧边栏「+ 目录」与目录右键「新建子目录」会**弹窗输入名称**后创建。
- 「+ 接口」新建接口后，在地址栏粘贴带 `?a=1&b=2` 的完整 URL，失焦会自动把查询参数解析进「Query 参数」。
- **目录宽度可拖拽**：将鼠标移到目录区与编辑区的分隔条上，按住左右拖动即可调整；
  宽度记在浏览器 `localStorage`，下次打开保持。目录默认折叠，避免层级过多时挤窄、卡顿。

### 1.5 多标签调试（类浏览器）

调试接口时支持同时打开多个接口窗口，互不干扰：

- **打开 / 切换标签**：左侧点击接口节点，若已存在该接口的标签则直接切换，否则新建标签。
- **新标签打开**：在接口节点上右键、或点击「⋯」更多菜单的「在新标签打开」，可强制新建一个独立标签（同一接口可开多个）。
- **关闭标签**：标签上的「×」或鼠标中键关闭当前标签；关闭当前标签会自动切到相邻标签，关闭最后一个回到空状态。
- **标签右键菜单**：在标签上右键可「关闭当前标签 / 关闭其他标签 / 关闭全部标签」。
- **独立记忆**：每个标签独立记住自己所在的子页（接口调试 / 参数设置 / 文档预览），切换标签不会丢失各自的视图状态。

### 2. 接口调试（请求区）

「调试」页顶部有一条**全局工具条**（环境选择、⚙ 环境管理、☰ 公共参数），下面是请求行，
请求行从左到右依次为：**方法、URL、发送、保存请求**。

- **环境管理（⚙ 环境）**：弹出「环境变量」面板，管理多套环境的 `{{变量}}`。
- **公共参数（☰ 公共参数）**：弹出「公共参数」面板，设置项目级统一 Header / Query。
  **它与环境变量位于同一维度**——一个管「本项目的公共请求头/参数」，一个管「不同环境的变量值」。
- **环境变量替换**：URL 与参数值中可用 `{{变量名}}` 引用当前激活环境的变量，
  发送时自动替换为对应值（仅启用项生效）。
- **保存请求（重要）**：调试时你可以随意修改、发送，但**发送不会自动覆盖已保存的接口定义**。
  只有点击「保存请求」才会把当前请求配置（地址、参数、请求体、脚本、响应）落盘，
  并**自动生成接口文档**（请求体 → 请求参数、响应体 → 响应参数）。该按钮始终可点击，
  方便在发送得到响应后随时生成/更新文档。
- **地址栏自动解析 Query**：在地址栏输入或粘贴带 `?a=1&b=2` 的 URL，失焦后会自动把查询参数
  解析进「Query 参数」列表，并从地址中移除，避免重复发送。
- **前后置脚本**：支持在请求前/后执行脚本（见下文）。

### 2.1 请求参数 / 请求头 / 请求体
切到「参数设置」标签页（或在调试页直接编辑）维护接口定义：

- **请求参数**：包含两部分——**Query 参数**（键值对，位于请求参数页顶部，可在此维护）
  - 「参数设置」内的所有编辑（字段、Query、请求头）**不会自动保存**，需点击该页右上角的「保存」或「接口调试」的「保存请求」才会落盘。
  与**请求体字段**（`reqFields`，Body 的字段结构，支持嵌套对象/数组）。
  - 可「粘贴 JSON 导入」「从请求体导入」「**从 Query 导入**」（把 Query 参数并入结构化请求参数文档，同名不重复）「AI 补全字段描述」。
  - 文档预览 / 导出时，Query 参数、请求头、请求体字段会分别成表展示。
- **响应参数**：响应 Body 的字段结构（`respFields`）。可「粘贴 JSON 导入」
  「从最近一次响应导入」「AI 补全字段描述」。
- **请求头**：该接口的请求头（`headers`，键值对），调试发送时一并生效；
  **Header 仅在此处编辑**，响应头不在接口定义中维护（见下方说明）。

> **关于 Header 的展示位置**
> 请求头（客户端发出，如 `Authorization`、`Content-Type`）统一在「请求头」标签页维护，
> 接口调试的**响应区只展示响应体**，不再额外展示「响应头」标签，避免与请求头重复。
> 因此「请求参数」「响应参数」的字段表格里**没有** Header 列，Header 只出现在「请求头」标签页。

### 3. 公共参数（对所有接口自动附加）

入口：**接口调试页 → 顶部的「☰ 公共参数」按钮**（与环境变量同一维度）。

- 可分别设置**公共 Header** 与**公共 Query**。
- 发送任意接口时，这些参数会**自动附加**到请求中；
- **接口自身已设置的同名参数优先**（接口覆盖公共），便于个别接口例外。
- 可配合环境变量 `{{变量}}`，例如公共 Header 填 `Authorization: Bearer {{token}}`。

> 示例：所有接口都需要带登录态时，只需在公共 Header 里加一条
> `Authorization = Bearer {{token}}`，不必在每个接口重复填写。

### 4. 环境变量

- 「环境变量」面板以横向环境芯片切换（开发/测试/生产…），编辑区占满宽度。
- 每行变量：`启用 / 变量名 / 值 / 说明`，可任意增删（变量行的新增/删除由编辑器自带的「添加一行」负责）。
- 切换「当前激活环境」后，调试时 `{{变量}}` 即使用该环境的值。
- 在 URL / Header / Body / Query 中以 `{{变量名}}` 引用；发送时当前环境的变量自动替换占位符。

### 5. 前后置脚本

调试页有「前置脚本」「后置脚本」两个标签页，执行前端 JS，可用于动态签名、取响应字段写回环境变量等。

**前置脚本**可用变量：
- `request.url` / `request.method` / `request.body`（JSON 时已是解析对象，可 `request.body.data.x`）/ `request.json()`
- `request.setHeader(k,v)` / `request.setQuery(k,v)`
- `setEnv(k,v)` / `env(k)` / `console.log()`

**后置脚本**可用变量：
- `response.status` / `response.headers`（对象，如 `response.headers["x-request-id"]`）
- `response.body`（JSON 时已是解析对象）/ `response.text`（原始字符串）/ `response.json()`
- `setEnv(k,v)` / `env(k)` / `console.log()`

**多种引用示例**：
```js
// 取响应体里的对象/数组字段，写回环境变量
setEnv("token", response.body.data.token)
setEnv("name",  response.body.data.list[0].name)
setEnv("xid",   response.headers["x-request-id"])

// 条件判断
if (response.status === 200) setEnv("ok", "1")

// 前置：用环境变量补全请求头/请求体
request.setHeader("X-Token", env("token"))
request.body.data.page = 1
```

### 6. 文档中心（导出与导入）

入口：顶部「📄 文档中心」。

- **选择范围**：按目录层级选择要导出的接口范围。
- **导出格式**：
  - Markdown（`.md`）— 适合 Git 仓库、Wiki
  - HTML（`.html`）— 带目录导航的网页文档
  - Word（`.doc`）— 可用 Office / WPS 打开编辑
  - OpenAPI 3.0（`.json`）— 可导入 Swagger、Postman、Apifox
- **复制 Markdown**：直接复制到剪贴板。
- **导入文档**：支持 OpenAPI 3.0 / Swagger 2.0 / Postman Collection（JSON 与 YAML），
  导入内容归入独立目录（以 `导入-<文件名>` 为根目录）。

  **目录分组规则**：
  - OpenAPI / Swagger 按文档中的 `tags` 创建目录，并把接口归入对应 tag。
  - 兼容 Apipost 等工具：即使文档**未在顶层声明 `tags`**，只要各接口自带
    `tags: ["用户管理"]` 之类标签，也会自动补建目录并归类。
  - Postman Collection 按其 `item` 的文件夹层级还原为多级目录。
  - **空目录自动剪枝**：导入后，没有任何接口（含其后代）的空目录会被自动删除，
    避免「导入后冒出一堆空文件夹」的问题。未归入任何目录的接口会落到导入根目录，不会丢失。

### 7. 分享文档

在接口或目录的右键菜单 / 文档中心中打开「分享」对话框，提供两种方式：

#### 方式 A：网页代码（独立 HTML，推荐）
- 生成**完整且样式内联的 HTML 源码**，**不依赖任何服务端**。
- 可「复制网页代码」「导出 .html 文件」「浏览器预览」。
- 把文件发给任何人或部署到任意静态服务器，对方都能直接打开。

#### 方式 B：在线链接
- **云分享（已配置云服务器并登录）**：文档上传到云服务器，
  生成公网链接 `https://你的云服务器/s/<token>`，任何人都可在浏览器打开（无需安装本程序）。
- **本地分享（未配置云服务器）**：由本工具内置本地服务托管（地址为 `127.0.0.1`，仅本机可访问），
  同一局域网内他人可将链接中的 `127.0.0.1` 替换为你的局域网 IP 访问；公网访问需改用云分享。
- 支持设置**访问密码**与**有效期**（10 分钟 / 1 小时 / 1 天 / 7 天 / 长期），并可随时「停止」某个分享。

### 8. 云同步 / 多端共享

入口：设置 → 「☁ 云同步 / 多端共享」。

- 填写云服务器地址，注册或登录账号。
- **推送到云端**：按项目 ID 创建或覆盖云端同名项目。
- **拉取**：点击云端项目即可拉取到本地并切换。
- **自动同步（开关）**：开启后每次编辑（防抖约 4 秒）自动把所有项目备份到云端，
  应用启动时自动拉取云端「比本地新」或「本地没有」的项目，实现多端无感同步。
- 冲突处理：若云端已有更新版本（HTTP 409），自动先拉取云端内容再合并，避免互相覆盖。
- 多端同时离线编辑同一项目时采用 last-write-wins；单人/单机防丢失完全没问题，多设备协作建议错开时间。

### 9. 内置同步服务（可选）

设置页可一键「启动服务」，桌面端同时作为同步服务器。
其他人可将云服务器地址填为 `http://你的IP:端口` 来连接（适合局域网或配合公网映射使用）。

### 10. AI 配置

设置页填写 OpenAI 兼容接口地址、API Key、模型，用于自动生成字段描述
（支持 OpenAI / DeepSeek / 通义千问 / 本地 Ollama 等）。

### 11. 版本与升级

- **本地配置文件**：数据保存在**程序启动目录下的 `apitool/` 子目录**（如 `apitool/data.json`），
  其中 `settings.version` 记录客户端版本号，`settings.updateURL` 记录升级服务地址
  （默认 `http://127.0.0.1:8080`）。首次启动若无配置文件会自动生成默认配置。
- **检测更新**：设置页「版本与升级」卡片显示当前版本、可编辑升级地址，点击「检测更新」
  会调用升级地址的 `/version` 接口。
  - 升级服务需返回 JSON：`{ "version": "1.2.0", "url": "下载地址", "notes": "更新说明" }`
  - 客户端按语义化版本号比较，服务端版本更高时提示「发现新版本」并给出下载入口。
- 升级服务端约定：`GET <升级地址>/version`，建议开启跨域 `Access-Control-Allow-Origin: *` 便于桌面端访问。

### 12. 剪贴板历史

桌面端在系统层面监听剪贴板变化，自动记录你**复制过的文本与图片**，无需打开主窗口即可随时调出、检索与复用。

**如何打开**
- **连续按两次 Ctrl**（两次间隔 ≤ 500ms）即可弹出 / 收起剪贴板历史浮层；
  该监听是全局的，即使主窗口最小化、隐藏到托盘甚至未聚焦也能触发。
- 也可在**系统托盘右键菜单 → 「剪贴板历史…」**打开。

**浮层操作**
- **搜索**：顶部输入框按内容实时过滤（图片项也可按时间检索）。
- **键盘导航**：`↑` / `↓` 在条目间移动，`Enter` 复制当前条目，`Delete` 删除当前条目，`Esc` 关闭浮层。
- **鼠标操作**：单击条目直接复制回剪贴板；右侧删除按钮移除该条。
- **文本**：复制后写入系统剪贴板，可粘贴到任意程序。
- **图片**：记录复制的图片缩略图，复制时以图片形式写回剪贴板（可在微信、文档等中粘贴）。

**设置**
- 入口：设置 → 「剪贴板」。`监控剪贴板`（开关）控制是否记录；`最大保留条数`限制历史上限，超出后自动丢弃最旧的条目。
- 记录保存在本地数据目录下的 `clipimg/` 子目录（图片以 PNG 存储），应用退出时清理被删除图片的文件。

> 说明：全局快捷键 `Ctrl+B`（弹出剪贴板历史）为固定行为，不依赖设置；其实现见 `hotkey_windows.go`（Windows 低级键盘钩子）+ `clipboard_windows.go`（剪贴板捕获 / 浮层窗口控制）。

### 13. AI Agent（智能助手）

左侧导航栏点击 **「Agent」** 进入 AI 智能助手，支持多轮对话、调用本地工具、累计 Token 统计。
Agent 复用「设置 → AI 配置」中的 OpenAI 兼容接口（兼容 OpenAI / DeepSeek / 通义千问 / 本地 Ollama 等）。

#### 13.1 多会话管理

- **新建会话**：点击左侧栏「+ 新建会话」按钮，每个会话独立保存上下文与历史。
- **切换 / 重命名 / 删除**：左侧会话列表中，点击切换；重命名、删除通过条目上的操作按钮完成。
- **继续对话**：在当前会话中直接发送新消息，Agent 会携带**本会话**的历史上下文（不会串到其他会话）。
- **会话隔离**：每个会话的对话内容、工具调用步骤、Token 消耗都独立记录，互不干扰。

#### 13.2 Token 统计

- 每次对话自动从流式响应中解析 `usage`（prompt / completion / total tokens），并实时累计。
- 每条会话显示**该会话累计 Token**；左侧栏底部显示**全局累计 Token**（输入 / 输出 / 合计）。
- 兼容性：请求时自动携带 `stream_options.include_usage=true`，并兼容 OpenAI 蛇形字段 `prompt_tokens`/`completion_tokens`/`total_tokens`，也兼容把 usage 放在任意分片（含最后一个带 `finish_reason` 的事件）的服务。
  > 注意：少数本地 / 老旧模型即使开启 `include_usage` 也不返回 usage，那种情况下 Token 会显示 0（属服务端限制）。

#### 13.3 内置工具（无需 MCP 服务器，本地直接执行）

设置页切到 **「内置工具」** 选项卡，可对每个工具**单独开关**、并**编辑其描述**（描述会作为工具说明传给模型，影响它何时调用）。工具以紧凑标签展示在对话中（仅显示名字，不展开大段内容）。

| 工具 | 图标 | 功能 | 关键参数 |
| --- | --- | --- | --- |
| `read_file` | 📄 | 读取文本文件内容（按 rune 截断，避免中文乱码） | `path`、`limit`（行数上限） |
| `write_file` | ✏️ | 写入文本文件（覆盖原内容） | `path`、`content` |
| `list_dir` | 📂 | 列出目录内容（文件/文件夹） | `path` |
| `make_dir` | 📁 | 创建目录（递归） | `path`、`all`(bool, 默认 true 递归) |
| `remove_dir` | 🗑️ | 删除目录 | `path`、`all`(bool, 默认 false 仅删空目录) |
| `remove_file` | ❌ | 删除文件 | `path` |
| `rename_path` | 🔀 | 重命名 / 移动文件或目录 | `src`、`dst` |
| `web_search` | 🔍 | 网页搜索（DuckDuckGo HTML），返回标题/摘要/链接 | `query`、`limit` |
| `system_info` | 💻 | 查看本机系统信息（OS/CPU/内存/主机名/时间/目录） | 无 |
| `get_time` | ⏰ | 获取当前日期时间（支持时区） | `timezone` |
| `calc` | 🧮 | 计算四则运算（仅 `+ - * / ()`） | `expr` |
| `run_command` | ⌨️ | 执行本地 shell 命令并返回输出（请谨慎使用） | `command` |

> 说明：`web_search` 依赖访问外网 DuckDuckGo，离线 / 网络受限环境可能失败；`run_command` 会在本机执行真实命令，使用前请确认信任当前对话内容。

#### 13.4 运行配置

设置页「运行配置」选项卡可调：

- **内容截断长度**（可配置，0 表示用默认）：
  - `工具输出回灌上限`（默认 4000 字符）：工具执行结果回传给模型前的最大字符数，调大可让模型看到更完整的工具结果。
  - `文件读取上限`（默认 200000 字符）：`read_file` 等内置文件工具读取的最大字符数。

#### 13.5 工具调用格式

Agent 提示词同时支持两种工具调用格式，模型任选其一（每轮最多一个工具调用）：

- **格式 A（标签，推荐）**：适用于原生支持 function calling 的模型
  ```xml
  <tool_call>
  <function>工具名</function>
  <parameter name="参数名">参数值</parameter>
  </tool_call>
  ```
- **格式 B（JSON）**：
  ```json
  {"action":"tool","server":"builtin","tool":"工具名","arguments":{...}}
  ```
  内置工具的 `server` 固定为 `builtin`。解析器兼容多种变体：函数名写在 `<function>` 体内或属性里、参数整体为 JSON 字符串、外层包裹 `<function_calls>` 等。对话中只展示**实际调用了的工具名字**标签，不罗列可用工具。

#### 13.6 MCP 服务器（stdio / 本地命令）

除了内置工具，Agent 还支持接入标准的 **MCP（Model Context Protocol）服务器**，从而调用社区/第三方工具（文件系统、数据库、搜索引擎等）。

进入 **设置 → Agent → MCP 服务器**，点击「新增服务器」并填写：

| 字段 | 说明 |
| --- | --- |
| `name` | 服务器显示名（对话中工具调用时会带上该名） |
| `transport` | 传输方式，选 `stdio` |
| `command` | **可执行命令或二进制完整路径**（见下方说明，**不是只填目录**） |
| `args` | 启动参数，空格分隔；可留空 |
| `env` | 额外的环境变量（可选，如 `API_KEY=xxx`） |

**`command` 的三种填法**（被 `exec.Command` 直接执行，等价于在终端里敲的命令）：

1. **命令名（已在系统 PATH 中）**——最省事：
   ```
   command: npx
   args:    -y @modelcontextprotocol/server-filesystem C:\你的目录
   ```
2. **完整二进制路径**（不在 PATH 时使用，Windows 路径用 `\\` 或 `/`）：
   ```
   command: C:\tools\mcp-server.exe
   args:    --port 8080
   ```
3. **目录 + 二进制**（同样是填**完整 exe 路径**，不会自动补 exe 名）：
   ```
   command: C:\tools\myserver\server.exe
   ```

> ⚠️ **不能只填目录**（如 `C:\tools\myserver`）：程序会把目录当成可执行文件去启动，会报「不是有效的 Win32 应用程序」或找不到文件。若希望「指目录就跑」，需目录内放一个约定名称的 exe，并**显式写出 `目录\xxx.exe`**。
>
> 路径本身含空格也能正确处理（因为是直接 `exec.Command` 而非走 shell），例如 `C:\Program Files\myserver\server.exe`。

**常见示例**：用官方 filesystem MCP 暴露某个本地目录给 Agent：
```
name:    文件系统
transport: stdio
command: npx
args:    -y @modelcontextprotocol/server-filesystem D:\task\data
```

**注意事项**：
- 当前 stdio 实现为**每次工具调用启动一次进程、完成后退出**（`exec.CommandContext` + 60s 超时），适合「一次性工具」。要求常驻会话、内部维护状态的标准 MCP server 可能不稳定，后续会升级为长连会话。
- 若 `command` 启动失败，对话会返回「启动 MCP 进程失败」；请优先确认命令在系统终端能独立跑通（含 npx / python 在 PATH 中）。
- 环境变量 `env` 会追加到进程环境，可用于注入密钥而无需写死在 args 中。

## 十四、网络抓包（MITM · 轻量 Charles / Fiddler 替代）

左侧导航栏点击 **「🕵 网络抓包」** 进入。ApiTool 内置一个本地 MITM（中间人）代理，
可实时解密经过本机的 HTTP/HTTPS 流量，并一键把抓到的请求**生成接口文档导入接口树**，
适合接口调试、逆向分析、移动端抓包等场景。

### 14.1 工作原理

- 启动后，ApiTool 在本机监听一个端口（默认 `127.0.0.1:8888`），作为 HTTP/HTTPS 代理。
- **解密 HTTPS 需要信任根证书**：HTTPS 流量经代理时会被 ApiTool 用内置 CA 动态重签，
  只有把该 CA 安装并信任到系统/浏览器，才能看到明文的请求与响应（否则 HTTPS 连接会被降级透传、不可解密）。
- 开启「切换系统代理」后，ApiTool 会改写系统的 `Internet Settings → Proxy`，
  让全系统的流量自动经过本代理（关闭时恢复），无需手动配置浏览器。

#### 支持的抓取协议

| 协议 | 是否解密解析 | 说明 |
| --- | --- | --- |
| HTTP / HTTPS | ✅ | 基础明文 / MITM 解密，记录请求头、Query、Body、响应体 |
| WebSocket / WSS | ✅ | 双向消息逐帧记录（C→S / S→C），标记 `websocket` 协议 |
| SSE（Server-Sent Events） | ✅ | 服务端流式推送事件记录，标记 `sse` 协议 |
| gRPC（HTTP/2 + protobuf） | ✅ | 经 HTTP/2 解密后做 protobuf  wire 解码，标记 `grpc` 协议 |
| GraphQL | ✅ | `application/graphql` 内容类型识别，作为 HTTP 子协议展示 |
| HTTP/2（h2） | ✅ | go-mitmproxy 已支持 h2 协商与 MITM，gRPC 即承载其上 |
| TLS（raw）/ SSH / FTP / SMTP | ⚠️ 仅识别不透传解密 | 字节嗅探识别协议类型，标记为不可解密（透传，不解析明文） |

> 除上述经 MITM 代理解密的协议外，还提供**浏览器扩展捕获**通道（`internal/capture`）：
> 通过扩展回传网页发出的 HTTP/HTTPS 请求，适合只关心页面接口、不想配置系统代理的场景。

### 14.2 快速开始

1. **安装根证书**：首次进入若提示「HTTPS 解密需安装根证书」，点击顶部「安装根证书」
   （Windows 需以**管理员身份**运行，程序会调用 `certutil -addstore Root` 把 CA 加入系统信任库）。
   安装后可在状态栏看到证书指纹（SHA1）。
2. **开始抓包**：点击「开始抓包」，状态栏显示「抓包中 · <监听地址>」。
3. **（可选）接管系统流量**：打开顶部「切换系统代理」开关，浏览器/应用的请求会自动经过代理。

> 性能说明：抓包数据采用**批量推送 + 40ms 节流 + requestAnimationFrame 合并渲染**，
> 列表上限 1000 条（保留最新），即使高并发流量也不会卡顿。
> **实时推送大 Body 自动截断**：单条请求/响应体超过 1MB 时，实时推送会截断并标记
> `[已截断]`（图片响应保留完整 base64 以支持预览），避免超大响应体通过 IPC 传输导致界面卡顿；
> 停止并保存后的会话仍保留**完整数据**，不影响历史查看与生成接口等功能。
> 移动端证书下载卡片**默认折叠**，点击状态栏「抓包中 · 地址」标签才展开，不挤压下方流量列表。
> 流量列表与详情面板采用固定布局（左侧列表、右侧详情自适应），无需手动拖拽分隔条。

### 14.3 实时流量列表（Charles 风格分组树）

左侧流量列表支持两种视图，可在工具栏切换：

- **分组树（默认）**：参照 Charles，按 `Host → 路径层级 → 具体请求` 三级（及以上）递归分组。
  **默认全部折叠**，手动点击展开箭头展开某一 Host / 目录；每行带选中计数与「全选/半选」勾选框。
- **平铺列表**：按时间顺序列出每一条请求，支持勾选批量操作。

列表每行以**彩色徽章**清晰区分（不再挤成一团）：

| 元素 | 颜色 |
| --- | --- |
| 协议 | `HTTPS` 蓝 / `HTTP` 绿 / `WebSocket` 紫 / `SSE` 橙 / `gRPC` 青 / `GraphQL` 粉 / `TLS` 橙 |
| 方法 | `GET` 绿 / `POST` 蓝 / `PUT` 橙 / `DELETE` 红 / `PATCH` 紫 / `HEAD`·`OPTIONS` 灰 |
| 状态码 | `2xx` 绿 / `3xx` 蓝 / `4xx` 橙 / `5xx` 红 |

**筛选**：顶部可按「关键字、协议（多选）、请求方法、状态码」实时过滤；协议/方法支持多选。
左侧的**「过滤条件」面板默认收起**（只占一行，把纵向空间让给流量列表），点击标题栏展开/收起；
收起时会在标题后显示**当前生效条件的一行摘要**与条件数量角标（如 `Host: api.test.cn · 排除: localhost · 协议: HTTPS`），
不会因折叠而看不清当前配置。面板内可设置 Host 过滤、排除 Host、协议勾选，以及「仅抓取 HTTP/HTTPS」「自动生成文档」开关。
协议勾选支持 `HTTP / HTTPS / WebSocket / SSE / gRPC / GraphQL`。
> 别名说明：勾选 `HTTP` 时自动包含 `HTTPS`，勾选 `WebSocket` 时自动包含 `WSS`（加密流量不再被漏抓）；
> 前端列表筛选与后端一致，勾选 `http` 也会匹配 `https`、`websocket` 匹配 `wss`。

**右键菜单**：在任一条流量上点击右键，弹出常用复制菜单：

- 复制地址（完整 URL）
- 复制为 curl 命令（bash，自动拼方法/URL/Header/Body，单引号正确转义）
- 复制原始请求（raw HTTP）
- 复制请求头 / 复制请求体 / 复制响应体
- 查看详情

### 14.4 详情面板（右侧）

选中某条流量后，右侧展示：

- **概览**：方法、URL、状态码、耗时、协议、Host、远端地址。
- **请求**：请求头、请求体（JSON 格式化高亮）、Query 参数。
- **响应**：响应头、响应体。
- **错误**：若连接/解密失败，显示错误类型与原因（如证书未信任、非 HTTP 流量、CONNECT 隧道等），并给出处理建议。

**响应体滚动**：响应体/请求体/头均采用 `pre` + `overflow:auto`，**长内容可上下、左右双向滚动**
（不再因折行丢失结构，也不被容器裁掉）。

#### 14.4.1 gRPC / GraphQL 解码

抓包对以下两类流量做了**应用层识别与解码**，无需额外配置：

- **gRPC（HTTP/2 上的 protobuf RPC）**
  - 识别依据：请求/响应 `Content-Type` 以 `application/grpc` 开头。go-mitmproxy 已对 HTTP/2（`h2`）做 MITM 解密，
    因此 gRPC 流量本就会被解密并标记为 `grpc` 协议。
  - 解码：自动剥离 gRPC 帧头（压缩标志 + 4 字节长度），对每个 message 做**通用 protobuf wire 解析**——
    字段号与类型被还原为 `field_1` / `field_2` 形式的可读 JSON（字符串/可打印内容直接展示，嵌套结构递归展开，
    数值按 int/float 呈现）。若 message 经 gzip 压缩（`compressed` 标志位 = 1），会先解压再解析。
  - 局限：零依赖解析**不依赖 `.proto` 文件**，能还原全部字符串内容与嵌套结构，但字段名显示为 `field_N`
    （protobuf 二进制不含字段名）。如需精确字段名，需提供 `.proto` 描述符做精确解码（后续增强）。
- **GraphQL**
  - 识别依据：`Content-Type` 为 `application/graphql`。作为 HTTP 子协议展示，请求体/响应体按原内容呈现。

**解压失败提示**：若响应/请求体为不支持的压缩算法（如部分 zstd 实现）导致 `DecodedBody` 失败，
详情面板「错误」区会给出「响应体/请求体解压失败（已保留原始数据）」提示，并保留原始字节以免信息丢失。

### 14.5 生成接口并导入接口树

勾选一条或多条（分组树可整组勾选），点击「生成接口并导入接口树」：

1. 选择目标**项目**与**目录**（目录树选择器）。
2. 程序按请求自动生成接口定义（方法、URL、Query、Header、Body 字段树），
   并以「批量导入（N）」方式写入左侧接口树，自动生成文档，省去手动录入。

> 适合把浏览器/Fiddler 里抓到的真实请求一键沉淀为可调试、可分享的接口文档。

### 14.6 抓包会话

点击顶部按钮栏的 **「抓包会话」**（位于「查看证书 / 导入证书」旁）打开独立弹窗管理，
**不占用主抓包界面**。弹窗内可：

- **加载/回放**某次会话的流量。
- **导出 OpenAPI**：把单个会话内请求导出为标准 OpenAPI 3.0（`.json`），可导入 Swagger / Postman / Apifox。
- **删除**：单条删除（带二次确认）。
- **一键清除会话包**：批量删除全部会话（带二次确认），快速清空历史记录。

> 抓包结果在「停止并保存」时会一并写入会话；也可在弹窗中刷新查看已保存的会话列表。

### 14.7 手机抓包（下载并安装根证书）

手机与电脑处于同一 Wi-Fi 时，可用本机作为代理抓取手机 HTTPS 流量：

1. 进入「网络抓包」并「开始抓包」（确保已安装本机根证书）。
2. 点击状态栏 **「抓包中 · <地址>」标签**（提示「点击看手机证书」）展开 **「📱 手机抓包证书」** 面板，
   给出两个地址（面板默认折叠，不占用主界面）：
   - **手机下载**：`http://<电脑局域网IP>:<端口>/proxy.pem`
   - **本机下载**：`http://127.0.0.1:<端口>/proxy.pem`
3. 手机 WLAN 设置里把 **HTTP 代理 → 手动**，服务器填电脑局域网 IP、端口填监听端口。
4. 手机浏览器打开「手机下载」地址，点击下载并安装根证书；
   iOS 还需到「设置 → 通用 → 关于本机 → 证书信任设置」中**启用对该证书的完全信任**。
5. 返回 ApiTool，手机上的 HTTPS 流量即实时出现在流量列表。

> 代理监听端口已内置证书下载路由：访问 `/proxy.pem`、`/cert`、`/ca.pem`、`/cert.pem`
> 均返回根 CA 证书（MIME `application/x-x509-ca-cert`）；直接访问根路径 `/` 返回一个
> 安装引导页（含下载按钮与 4 步说明），方便手机直接打开。

### 14.8 导入外部根证书（复用 Fiddler / Charles CA）

若你已在系统信任了 Fiddler / Charles 的 CA，可在「导入证书」对话框中粘贴其
**证书 PEM** 与**私钥 PEM**，ApiTool 会复用该 CA 进行重签，避免重复安装、并保持与既有抓包工具的信任链一致。

### 14.9 请求改写（域名重定向 + 参数替换）

点击顶部按钮栏的 **「请求改写」**（黄色按钮）打开弹窗维护规则，把请求的域名改写为指定地址，
适合**把线上域名指向本地联调服务**，例如 `dev.test.com → 127.0.0.1:8200`：

| 字段 | 说明 |
| --- | --- |
| 启用 | 开关，停用的规则不参与匹配 |
| From（原域名） | 匹配请求的域名（忽略端口与大小写），支持通配前缀 `*.example.com` 匹配任意子域 |
| To（改写地址） | 目标地址，支持 `127.0.0.1:8200`、`10.0.0.5:8080` 等 IP:端口，**也支持直接填域名**（如 `api.example.com`，未写端口时按转发协议自动补 `:443`/`:80`），可用于域名之间的相互重定向；**还可带路径与查询串**（如 `api.example.com/v2/api?v=2`），命中后整体替换原请求的路径与参数 |
| 协议 | 可选「自动 / HTTP / HTTPS」；显式指定优先 |
| 参数 | 打开该规则的「参数替换」弹窗，自由替换 Query 参数 / 请求头（详见下方），按钮上会显示已配项数 |
| 描述 | 备注说明 |

**转发协议判定**：未显式指定时，目标**带端口且端口 ≠ 443 → 按 HTTP 转发**（本地联调服务通常为明文
HTTP，避免报 `server gave HTTP response to HTTPS client`）；端口为 443 或无端口时跟随原请求 scheme。
目标未带端口时按最终 scheme 补默认端口（HTTPS `:443` / HTTP `:80`）。

**HTTPS 处理**：对 `CONNECT` 请求不做改写，证书仍按**原域名**签发（信任链不受影响）；
解密后的内层请求自然命中改写规则后转发到目标地址。

规则**持久化**在 CA 同目录的 `rewrites.json`，保存后立即对后续抓到的请求生效，无需重启抓包。
典型的本地联调流程：开启抓包 → 配置 `线上域名 → 127.0.0.1:8200` → 正常请求线上地址，
流量实际打到本地服务，同时请求/响应仍以线上域名展示、可正常生成接口文档。

#### 自由参数替换

在规则行点击 **「参数」** 打开参数替换弹窗，可对命中该规则的请求做**任意参数**的替换、新增与删除：

| 字段 | 说明 |
| --- | --- |
| 启用 | 停用该项不参与替换 |
| 类型 | `Query 参数`（URL 查询串，如 `?token=xxx`）或 `请求头`（HTTP Header，如 `Authorization`、`Host`） |
| 操作 | `替换/新增`：覆盖同名参数的值，原请求没有该参数时自动追加；`删除`：移除该参数 |
| 参数名 (Key) | 要替换的参数名，留空的行关闭弹窗时自动丢弃 |
| 替换为 (Value) | 新值，`替换` 时生效（留空即把值置空）；`删除` 时无需填写 |

替换项**按从上到下的顺序依次执行**，因此可以组合出复杂规则（先删旧参数，再追加新参数）。典型用法：

| 场景 | 配置 |
| --- | --- |
| 固定测试 token | Query 参数 `token` → 替换为 `test_token`（请求未带 token 时自动加上） |
| 切换环境标识 | Query 参数 `env` → 替换为 `prod` |
| 改写鉴权头 | 请求头 `Authorization` → 替换为 `Bearer xxx` |
| 去掉干扰参数 | Query 参数 `sign` → 删除 |
| 换域名 + 改整套参数 | To 填 `api.example.com/v2/api?v=2`，再用参数项微调个别参数 |

> 说明：替换发生在**请求发出前**，因此抓包列表里看到的、以及「生成接口」用的都是**替换后**的请求；
> 想看原始请求停用规则即可。Query 替换会保留未命中参数的原始顺序与编码；
> Header 替换按标准 Header 语义处理（名不区分大小写，同名键只保留一个值）。

### 14.10 常见抓包问题排查

- **HTTPS 显示「证书未信任 / 连接被重置」**：未安装或未信任根证书。点「安装根证书」并以管理员运行；
  浏览器若仍报错，检查系统/浏览器证书管理器里 ApiTool CA 是否存在并设为信任。
- **抓不到手机流量**：确认手机与电脑同 Wi-Fi、代理 IP/端口正确、手机已访问过一次网络、
  且手机端证书已安装并（iOS）启用完全信任；部分 App 会走系统代理之外的通道（如 HTTP/3、直连 IP），可能抓不到。
- **抓不到系统流量**：确认已开启「切换系统代理」开关；部分程序（如某些命令行工具）会忽略系统代理，需在其内单独配置。
- **只看到 CONNECT / TLS，看不到明文**：仍未解密成功（证书未信任），按上面排查。
- **首次开启抓包「等半天」**：代理启动已改为后台 goroutine + 500ms 超时，点击后立即生效；若仍慢多为证书信任检查阻塞，可先装好证书。

### 14.11 目录结构与实现

- 后端：`internal/sniff/`
  - `proxy.go`：MITM 代理与 addon（请求/响应/WebSocket/SSE hook）、协议识别 `protocolOf`、过滤 `shouldIntercept`、错误标记。
  - `protocol.go`：`IdentifyProtocol` 原始流量嗅探、`matchProtocol` 协议匹配（含 `https→http`、`wss→websocket` 别名）、`ProtocolOptions` 协议枚举（统一来源）。
  - `grpc.go`：gRPC 帧解析 + 通用 protobuf wire 解码（支持 gzip 压缩 payload）。
  - `manager.go`：抓包生命周期 / 状态、`Filter` 配置（Host/Method/Path/Protocol/Keyword）、实时推送大 body 剪裁。
  - `session.go`：抓包会话的存储 / 加载 / 删除 / OpenAPI 导出。
  - `rewrite.go`：请求改写规则（域名匹配与重定向、转发协议判定、Query/Header 参数替换、持久化 `rewrites.json`）。
  - `sysproxy.go`：系统代理接管与证书信任管理。
  - `ca.go`：CA 生成与重签。
  - `capture.go`：记录去重、浏览器扩展回传的流量捕获（含静态资源过滤与 OPTIONS 预检去重）。
- 前端：`frontend/src/components/mitm/`（`MitmPanel.vue` 主面板、`GroupTreeNode.vue` 递归分组树节点）。

**浏览器扩展捕获增强**：`internal/capture/capture.go` 在回传流量入库前做了服务端兜底过滤——
除 URL 扩展名判定静态资源（js/css/图片/字体/音视频/pdf/wasm 等）外，还依据响应 `Content-Type`
（image/*、audio/*、video/*、octet-stream、字体、pdf）兜底过滤二进制流；并对同一 URL 已存在
非 OPTIONS 业务记录时的 **CORS 预检（OPTIONS）请求做去重**，避免无业务价值的请求堆积。

## 四、部署云分享服务器（公网访问文档）

## 五、数据存储

应用支持两种后端存储，**结构化数据（项目/接口/目录/用例/计划/报告/设置/插件连接/剪贴板等）统一入库**，
接口文档（Markdown / HTML / Word / OpenAPI）以及 Agent 数据仍按原方式以文件保存（见 5.3）。

### 5.0 数据根目录

所有本地数据文件统一存放在**「程序可执行文件所在目录」下的 `apitool/` 子目录**（即 exe 同级 `apitool/`，
不占用系统用户配置目录如 `%APPDATA%`）。该目录下包含：

- `apitool.db` —— SQLite 主数据库（默认）
- `data.json` / `storage.json` —— JSON 回退 / MySQL 切换配置
- `agent.json` —— Agent（MCP / 会话）数据
- `syncserver/` —— 内置同步服务数据
- `clipimg/` —— 剪贴板图片缓存

因此**迁移 / 打包程序时，只需把整个 `apitool/` 目录连同 exe 一起复制**即可带走所有数据。
旧版本位于 `%APPDATA%/apitool` 的数据，整体复制到 exe 同级的 `apitool/` 目录即可沿用。

### 5.1 默认：SQLite（本地文件）

- 数据保存在程序启动目录下的 `apitool/apitool.db`，首次启动自动建表。
- 若同目录存在旧版 `data.json`，会在首次启动时**自动导入** SQLite（原 `data.json` 保留作为备份）。
- 采用纯 Go 实现的 SQLite 驱动（modernc.org/sqlite），无需额外运行时，跨平台一致。

### 5.2 可选：MySQL（远程 / 共享）

- 在 `apitool/`（程序启动目录下的数据子目录）放置 `storage.json` 即可切换到 MySQL：
  ```json
  { "type": "mysql", "dsn": "user:pass@tcp(127.0.0.1:3306)/apitool?parseTime=true&charset=utf8mb4" }
  ```
- 程序启动时会自动建表（与 SQLite 完全相同的 schema），适合多人/多端共享同一份数据。
- 数据库不可用时（文件损坏、连接失败）会自动**回退到 JSON 文件模式**，保证程序不崩溃。

### 5.3 存储范围与例外

**已入库的结构化数据**（11 张表，SQLite/MySQL 通用 schema）：

| 表 | 内容 |
| --- | --- |
| `meta` | 单例元数据（`version`、`updateURL`） |
| `projects` | 项目（名称、公共参数、环境变量开关、文档目录、UI 状态等） |
| `directories` | 接口目录树 |
| `apis` | 接口（请求/响应、Header/Query、前后置脚本、字段树、最近响应） |
| `environments` | 环境变量（按项目） |
| `test_cases` | 测试用例（含步骤、断言、数据集） |
| `test_plans` | 测试计划（关联的用例、环境、并发数） |
| `test_reports` | 测试报告（通过/失败统计、耗时、结果明细） |
| `settings` | 全局设置（代理、外观、AI、云同步、升级等） |
| `plugin_conns` | 插件数据库连接配置 |
| `clip_items` | 剪贴板历史（文本/图片元数据） |

**不入库、仍以独立文件保存的数据**：

- **Agent 数据**（`agent.json`）：MCP 服务器配置、多会话（含各自的 `messages` / `usage`）、内置工具开关、累计 Token。由 agent 模块独立管理，不进入上述数据库，保证 Agent 对话与接口数据隔离、可单独备份。
- **接口文档**（md / html / word / openapi）：由「文档中心」按需导出为文件，不入库。
- **分享快照**：本地分享服务按请求实时渲染，不落到数据库。
- **云服务器端数据**：保存在 `-data` 指定的目录（账号、项目、分享文档），为独立的服务端存储。

> 说明：数据库不可用时（文件损坏、连接失败）会自动**回退到 JSON 文件模式**（`data.json`），保证程序不崩溃。

## 六、常见问题

**Q：分享的「在线链接」别人打不开？**
A：未配置云服务器时为本地分享，仅同局域网可访问。要公网访问，请部署云同步服务器并在设置中登录。

**Q：环境变量 `{{变量}}` 没被替换？**
A：请确认该变量所在环境为「当前激活环境」且「启用」开关已打开，变量名与 `{{ }}` 内一致。

**Q：公共参数没生效？**
A：请确认公共参数已启用（勾选），且接口自身没有同名的 Header/Query（接口值会覆盖公共值）。

**Q：项目名称无法修改？**
A：通过顶部项目下拉框右侧「⋯」→「重命名当前项目」修改。

**Q：发送请求后，接口定义 / 文档没更新？**
A：这是设计使然——**发送不会自动保存**，避免把临时调试改动覆盖到已保存的接口。
点击「保存请求」才会落盘，并自动用请求体 / 响应体生成或更新文档（按钮始终可点击）。

**Q：Query 参数没出现在「请求参数」里？**
A：「参数设置 → 请求参数」页顶部即为 Query 参数（可编辑）；也可点「从 Query 导入」将其并入结构化请求参数文档。文档预览与导出中 Query 参数会单独成表展示。导入接口文档（OpenAPI 等）只在「文档中心」进行，接口测试页不再重复提供。

**Q：如何把他人发来的接口文档导入？**
A：文档中心 → 导入，支持 OpenAPI / Swagger / Postman 的 JSON 或 YAML。导入后空目录会被自动清理。

**Q：目录太宽/太窄？**
A：将鼠标移到目录区与编辑区之间的分隔条拖动即可调整宽度，宽度会被记住。

**Q：从 Apipost 导出的 OpenAPI 3.0 导入后，接口没有按目录分组？**
A：旧版本仅识别顶层 `tags` 数组，而 Apipost 常在接口内自带 `tags` 但未在顶层声明，
导致全部平铺。当前版本已支持「接口自带 tag 也自动建目录」；若导入后仍平铺，请确认
导出文件里每个接口带有 `tags` 字段。无接口的空目录会被自动剪枝。

**Q：为什么在「接口调试」里改了 URL/参数，没点「保存请求」也会保留，但文档没更新？**
A：调试区为「发送不自动保存」设计：内联编辑会抑制自动保存，避免误改污染已存文档；
只有点「保存请求」才把当前接口落盘并刷新「文档预览」。环境、公共参数、重命名等元数据编辑则会防抖自动保存。
若切换/重启后发现调试改动丢失，多半是没点保存——这是有意设计，并非丢数据。

**Q：数据很多时输入/切换有点卡，正常吗？有什么注意点？**
A：已针对大体积数据做性能优化：自动保存走轻量修订信号而非全量深监听，保存时只刷新当前接口快照，
不克隆全部接口。正常使用应较流畅；若仍感卡，通常是单接口 Body/响应体过大或同时开了极多标签，可分批调试。

**Q：开启「自动同步云端」后数据还会丢吗？**
A：本地每次编辑会防抖推送到云端，云端始终保留最新副本，可避免本地文件损坏/误删导致丢失。
多设备同时离线编辑同一项目时后同步一方会覆盖先同步一方（last-write-wins），重要协作建议错开时间或善用「拉取」兜底。

**Q：用 `npm run dev` 浏览器预览，点「生成分享链接 / 发送请求」报错
`Cannot read properties of undefined (reading 'main')`？**
A：这是预期行为——浏览器预览环境没有 Go 后端（`window.go` 由 Wails 运行时注入）。
程序已做安全兜底：会显示「当前环境未连接到 Go 后端…」的友好提示而非白屏崩溃。
要真正使用分享、云同步、发送请求等功能，请用桌面端 `wails build` 构建后运行，或 `wails dev` 实时预览。

**Q：桌面端仍然报 `reading 'main'` 错误？**
A：说明 Wails 桥接未正确注入。请确认用 `wails build` / `wails dev` 启动，而非直接打开
`npm run build` 产出的 `dist`。如仍异常，尝试删除 `frontend/dist` 与 `build/bin` 后重新 `wails build`。
